# Операционные системы - базовые предпосылки и контекст возникновения

**Операционная система — базовое системное программное обеспечение, управляющее работой вычислительного узла.**  
Посредник между аппаратным обеспечением, прикладным ПО и пользователями.

## Предпосылки
Изначально компьютеры были мэйнфреймами, обрабатывающими большое число однотипных задач.
Наличие нескольких операторов\терминалов у одной ЭВМ - неудобно.  
С развитием телефонных сетей компьютеры круто пригодились в обработке однотипных
данных из разных мест, возникла потребность в дележе ресурсов - времени, памяти,
работы с периферийными устройствами, многопользовательский режим.
* Множество приложений используют общие ресурсы: процессор, память, хранилища.
* Многопользовательские системы требуют разграничения доступа к ресурсам.

## Этапы
Исследователи выделяют четыре или пять этапов развития ОС.
### 1. Однозадачные (монопрограммные) системы, архитектура фон Неймана.
Период: 1950-е — начало 1960-х
Железо: мейнфреймы, перфокарты
Особенности:

* Одновременно выполняется только одна программа.
* Нет разделения времени.
* Нет взаимодействия между задачами.
* Пользователь полностью использует машину.

Пример: ранние системы IBM 701, IBM 704.

#### Основные компоненты:   
- центральный процессор
- оперативная память
- устройство ввода-вывода
- постоянное запоминающее устройство.

#### Принципы архитектуры фон Неймана
- **Однородность памяти**: код и данные находятся в единой памяти.
- **Адресность**: линейная система адресов в оперативной памяти.
- **Произвольный доступ**: процессор может получить доступ к любой ячейке памяти.
- **Программное управление**: последовательность команд в памяти, выбор следующей команды на каждом шаге.

#### Принцип работы программы
* Программа начинается с точки входа.
* На каждом такте выбирается следующая команда для исполнения.
* Команда может быть точкой ветвления: проверка условия и переход в другую область кода.

#### Принцип кодирования
* Используется двоичное кодирование для кодов команд и данных.
* Первый этап эволюции операционных систем — программы-диспетчеры.

### 2. Пакетная обработка (Batch Processing Systems)
Период: 1960-е
Особенности:
* Программы объединяются в пакеты (batch jobs).
* ОС автоматически запускает одно за другим.
* Минимум взаимодействия с человеком.
* Появление спулинга (асинхронное взаимодействие с периферией, 
например вывод на печать через спул-файл с очередью).

Пример: IBM OS/360 (частично).

Сначало как было:  
Загрузка и выполнение пакетов последовательно, без остановки.
Надо подчеркнуть, что параллелизма не было.
При этом:
* Пакеты могут иметь разных владельцев и требовать управления очередью.
* Необходимо вводить приоритизацию для ускорения выполнения некоторых пакетов.
* Логика выполнения пакетов может зависеть от их характеристик.

Пример из супермаркета (приоритизация)
* В очереди в супермаркете разные люди имеют разные потребности: кто-то с большой тележкой, кто-то с маленькой корзинкой,
кто-то с одной бутылкой воды.
* Эффективное управление очередью позволяет пропустить вперёд тех, кто быстрее выполняет свои задачи.
* Это повышает эффективность системы в целом.

#### Возникновение базовых ОС-решений
Итак, возникла потребность одновременного параллельного запуска программ, которые, к тому же,
зачастую, выполняют много похожих действий.
* **Проблема**: необходимость повторного использования фрагментов кода, риски ошибок.
* **Решение**: фиксация кода часто используемых подпрограмм в оперативной памяти.

Всё хранить в памяти невозможно. Оперативки было вообще мало и она была дорогой.
* **Проблема**:
    * Увеличение размеров обрабатываемых данных.
    * Ограниченность оперативной памяти и необходимость оптимизации взаимодействия с долговременной памятью.
* **Решение**:
    * Идея подгрузки данных по мере необходимости и потоковой обработки.
    * Идея создания параллельного потока для перемещения данных между хранилищем и оперативной памятью.
    * Введение аппаратного контроллера для управления подкачкой и откачкой данных.

То есть, появились уже служебные посреднические компоненты.

* **Проблема**: 
  * Необходимость в системе управления для идентификации адресов 
  подпрограмм, ведь вручную управлять сложно. 
  * Необходимость передачи динамических
  параметров программам.
* **Решение**: 
  * Создание специального программного обеспечения для 
  автоматизации загрузки и линковки.

То есть помимо аппаратного управления, возникло ещё и программное посредничество.
Эти требования копились.

* **Проблема**:
    * Программы конкурируют за переферийные устройства, возможны коллизии. 
* **Решение**:
    * Механизм прерываний для управления передачей данных между контроллером и процессором.
    * Прерывание как сигнал от контроллера к процессору о завершении операции.


#### О прерываниях

* Процессор продолжает выполнять код во время передачи данных контроллером.
* При завершении операции контроллер генерирует прерывание, которое останавливает текущий набор команд процессора.
* Обработка прерывания позволяет процессору перейти к следующей ветке кода.

Изначально был вообще только 1 тип перрываний - исходя из потребностей - это прерывание ввода-вывода.

**Спулинг** (Simultaneous Peripheral Operations On-Line) - 
Оптимизация взаимодействия с периферийными устройствами через спулинг.

Все эти оптимизации привели к развитию ...
### 3. Мультипрограммные операционные системы (Time-Sharing Systems, TSS)

* Программы имеют разный профиль использования ресурсов, **например**, 
растровая и векторная графика. 
  * Растровая графика требует быстрой обработки больших объёмов данных, а векторная — быстрых вычислений.
  * Вычислительный узел должен быть универсальным для разных задач.

**Примеры**: Multics, ранние версии UNIX.

### 4. Системы с разделением ресурсов и виртуальной памятью
42:50 Параллельная работа программ

* Параллельная работа нескольких программ позволяет эффективнее использовать ресурсы.
* Возникают проблемы с переключением между программами, разделением памяти и правами доступа.
* Мультипрограммные ОС решают эти проблемы, становясь универсальным интерфейсом между железом, ресурсами, ПО и пользователями.

**Примеры**: UNIX System V, BSD, VMS.

### 5. Распределённые, сетевые и персональные ОС
Период: 1980-е — наши дни  

**Особенности**:
* Поддержка сети, удалённых файловых систем.
* Аппаратная и программная переносимость.
* Появление домашних и персональных ОС.
* Распределённые вычисления, кластеризация.
